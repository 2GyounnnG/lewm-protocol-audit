# C 并行运行补充

作者于 2026-10-14 UTC 提供 SSH，并要求只运行 C、两路并行，条件允许则四路。method_hold 不部署、不运行。

新实例暴露两张 NVIDIA GeForce RTX 4090，各报告 49140 MiB。采用 AP 原入口已有的 --shards / --shard-index 分片，不修改入口、case 顺序、query ordinal、随机种子、模型或统计定义。主表先完成；附录按 42、43、44 顺序，每组内部使用已验证并发数。

技术门仍先以原脚本通过。之后先对主表前四例做两路检查（一卡一进程），再以相同四例做四路检查（一卡两进程），比较同 case 的全部动作、成功和首次成功步；必须一致。四路必须无 OOM、显存留有余量，且总吞吐比两路提升才采用。若四路失败或不提速，保留失败记录并回退两路；两路不满足一致性则不启动正式运行并报告。

并发进程共享只读数据/缓存，各自输出原生分片记录。GPU 总预算保持 6 小时；并行批次按物理设备数量乘批次墙钟累计，四进程在两卡上不会误计为四卡，也不会误计为单卡。建库、技术门、并发测试和正式阶段均计入累计。正式前另据实测并发吞吐做剩余预算核验。

每阶段回传并逐文件 SHA 核验，正式阶段至少每 30 分钟增量回传。最终核验后 stop 当前实例，不 destroy。未核验不进入下一阶段。
